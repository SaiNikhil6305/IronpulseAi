## Builds

```bash
flutter pub get
# Device-only build (no backend needed; sign-in/AI show "not configured"):
flutter build apk --debug
# Full build with your public config:
flutter build apk --release --dart-define-from-file=config/app_config.json
flutter build appbundle --release --dart-define-from-file=config/app_config.json   # for Google Play
```

| Output | Path | Use |
|---|---|---|
| Debug APK | `build/app/outputs/flutter-apk/app-debug.apk` | Testing; larger, slower, debuggable |
| Release APK | `build/app/outputs/flutter-apk/app-release.apk` | Side-loading / testers; optimised |
| App Bundle | `build/app/outputs/bundle/release/app-release.aab` | Upload to Google Play (Play generates per-device APKs) |

## Release signing

Without `android/key.properties` the release build is signed with the **debug key** — fine for testing,
**not** for Play distribution or long-term installs (you can't update an app signed with a different key).

```bash
keytool -genkey -v -keystore ~/ironpulse-upload.jks -keyalg RSA -keysize 2048 -validity 10000 -alias upload
cat > android/key.properties <<EOF
storePassword=…
keyPassword=…
keyAlias=upload
storeFile=/absolute/path/to/ironpulse-upload.jks
EOF
```

`key.properties`, `*.jks` and `*.keystore` are git-ignored. In CI, store the keystore as a base64 secret
(`ANDROID_KEYSTORE_BASE64` etc. — see `.github/workflows/ci.yml`). Enrol in **Play App Signing** and add the
upload and app-signing SHA-1s to Google Cloud (AUTH_SETUP.md).

## Install the APK on a phone

1. Copy the `.apk` to the phone (USB, Google Drive, or `adb install app-release.apk`).
2. Open it from Files. When asked, allow **Install unknown apps** for that app (Settings → Apps → Special app
   access → Install unknown apps). Only do this for APKs you built yourself.
3. Install and open **IronPulse**.
4. Without backend config: tap **Use on this device only**, finish onboarding, pick a split, start a workout,
   log a set, close the app, reopen → the workout resumes.
5. With backend config: sign up / sign in (email or Google) and run the checklist in AUTH_SETUP.md.

## Play Store preparation

* Data safety form: see PRIVACY_AND_COMPLIANCE.md (health & fitness data, email, photos, app activity; encrypted
  in transit; deletion available in-app).
* Health Connect: submit the Health Connect permissions declaration; the app shows its privacy policy from the
  permissions screen (activity-alias in the manifest) — host the policy and link it in the store listing.
* Exact alarms are **not** used (reminders use inexact scheduling), so no `SCHEDULE_EXACT_ALARM` declaration.
